# 大肥鱼 PWA 首版设计

日期：2026-11-13。状态：用户已接受 PWA 及非商业素材复用，并要求开始开发；开发版已验证，正式付费云资源尚未获准购买。实施及验证记录见对应计划。

## 已确认的目标

- 形态参考“会说话的汤姆猫”：有可见角色，能互动、聊天和说话。
- 首版采用 PWA，供家人朋友通过手机和电脑使用。
- 核心服务在云端运行；本地电脑或 WSL 停机不影响正常聊天。
- 每个人的聊天记录和记忆独立；同一账号换设备可以继续使用。
- 本地用于开发和备份，不是在线请求的必经节点。

## 范围及方案比较

| 方案 | 收益 | 代价 | 决定 |
| --- | --- | --- | --- |
| 云端核心 + PWA + 本地备份 | 一份客户端覆盖多种设备，核心服务不依赖家中电脑 | 需要云端持久化和语音实机兼容验证 | 用户已选择 |
| 云端核心 + Android 原生 | 更深入的手机系统集成 | 苹果、电脑需另建客户端 | 暂缓 |
| 本地核心 + 云端中转 | 核心数据主要留在本地 | 本地停机则完整聊天中断 | 不满足已确认目标 |

首版交付邀请注册、账号登录、二维角色、动作按钮、文字聊天、按住录音后发送、语音回复、个人记忆管理、跨设备续聊、备份恢复。角色先有待机、眨眼、点击反应、聆听、思考、说话六类状态，并支持用户通过按钮触发指定动作；不承诺精细口型。动作按钮是用户在初稿后新增的明确需求，具体动作名单仍为下文建议。

首版不做三维角色、复杂养成和小游戏、持续监听、后台或锁屏语音、实时插话打断、公开注册、收费体系、应用商店发布、QQ 记忆导入或互通。不复制汤姆猫素材。

## 提议的默认值（设计者建议，待本文整体确认）

- 面向约 5～20 个受邀账号、初期约 3 人同时聊天；这是容量验证基线，不是用户已提供的人数。
- 中文优先；支持 Android Chrome、iPhone Safari 和 Windows Edge/Chrome 的当前常用版本，记录实际测试版本。不同浏览器的桌面安装方式可以不同。
- 首版只在前台交互；录音一次最多 60 秒，支持取消。麦克风拒绝时仍可文字聊天。
- 同一个人多设备共享一份连续对话；每账号一次只生成一条回复，其他请求明确排队或提示重试，不无声丢弃。
- 登录方式为邀请后设置用户名和密码；管理员生成单次、有限期邀请链接。不引入短信计费或邮箱发送依赖。
- 模型沿用现有兼容 API 的接入能力。具体提供商、模型、ASR 和 TTS 服务由连通性、费用与实机语音验证决定；不承诺现有个人语音调用方式适合多人服务。
- 原始录音只作识别中转，默认在处理完成或过期后删除，不进入长期备份；合成音频使用短时缓存。

这些默认值可修改；不得将其描述成用户已明确指定。

## 架构与部署

PWA 通过同源 HTTPS 请求云端 Node.js 服务，服务调用对话模型及语音接口。账号、会话、消息、个人记忆和角色关系状态使用云端持久化数据库。模型密钥只放服务端。

首版采用一个应用实例，复用现有 Node.js 对话引擎，避免增加独立队列、微服务或向量数据库。建议首版用单实例 SQLite 持久磁盘，利用现有 SQLite 记忆能力；禁止把数据写在 Render 免费实例的临时目录。若所选宿主不能提供持久磁盘，需在部署前改为持久化托管数据库并验证迁移，不能降级为会丢数据的运行方式。

正式部署须选不因空闲休眠的应用实例、持久化存储和独立备份位置；这通常产生费用。已有免费测试页仅供连通性演示，不承载正式账号与记忆。正式资源的套餐、地区、每月预算和付费授权必须在生产部署前确认；本设计不授权购买付费资源。

本地备份由电脑主动从受保护的备份入口拉取，无需向公网暴露本地端口。本地离线时云端仍照常服务，云端独立备份也继续执行。共享 API 失败时显示暂不可用，不切换成依赖本地电脑的隐式后备路径。

## 现有代码复用与必须调整的边界

- `src/chat/engine.js`：复用对话、人设、记忆召回等能力，新增面向 App 的受鉴权入口。
- `src/app.js`：目前混合了 QQ 消息流程、语音及存储初始化；新增独立 App 组装入口，不能靠启动 NapCat 才能使用。
- `src/chat/event-memory.js`、`personal-memory.js`：当前身份与 scope 含 QQ 平台语义；需明确支持 App 的私人场景。`engine.js` 目前也显式判断 `napcat-private`，新平台不能被当成群聊。
- QQ 亲友名单、爸爸称呼和 QQ 号关系不能自动应用到同名 App 账号。App 的关系按自身账号配置；用户不能通过改昵称取得特殊身份。
- 现有 JSON 记忆与 SQLite 存档不能当作两个可任意写入的主数据库。持久化改动应定义清晰的数据归属、版本及迁移方式，并保留现有 QQ 行为的回归证据。
- `src/voice/` 可复用调用方式与清理逻辑，但必须验证云端依赖、并发、超时及多人使用成本。
- 不向公网公开现有 `admin/server.js`。管理入口须单独鉴权，模型密钥不能进入 PWA。
- 现有 Android 工程保持独立，暂不继续捆绑 Linux QQ/PRoot 到新客户端。

## 身份、记忆与隔离

服务器生成不可猜测且稳定的内部 user_id。所有会话、消息、长期记忆、模型摘要、异步任务、音频文件和角色状态均带所有者身份。请求中的用户身份来自已验证的登录会话，客户端传来的 user_id 不作为授权依据。

所有读取、搜索、写入、导出、删除、任务结果获取和音频下载都按用户所有权检查。模型上下文组装也只能读取当前用户的数据；不能只靠提示词阻止串记忆。缓存键与后台任务也必须含用户范围。

同一账号跨设备保持连续性；不同账号只共享经过审阅的角色基础人设和公开资源，不共享私人经历、关系进度和聊天摘要。

会话使用安全 Cookie（HttpOnly、Secure、合适的 SameSite），会话可失效与退出；密码使用带随机盐的可靠哈希。状态变更接口采取 CSRF/同源校验，邀请、登录、聊天与音频接口有限流和体积上限。

PWA 仅缓存公开程序资源。私人聊天接口、录音、账号信息和音频不进入通用 Service Worker 缓存。退出或换账号清除私有内存及临时状态；共享设备不能显示上一账号内容。

普通用户不能查看别人的聊天。管理员首版界面只管理邀请、账号状态、配额和服务状态，不提供浏览他人原文的入口。但服务器与备份由运维持有，不宣称端到端加密或管理员技术上绝对不可读；用户应在录音/聊天前看到简短的数据与第三方处理说明。

用户能查看和删除个人长期记忆，能清空聊天。删除需同时处理原文、摘要、检索数据及未完成任务，防止异步任务把删除内容写回；历史备份中的副本按保留期到期清除。恢复旧备份时必须重放备份之后的删除记录，禁止让已删除数据重新进入在线记忆。

## 聊天、语音与角色行为

文本先完成可靠闭环；网络超时或重复点击通过请求标识去重。刷新后能查询已持久化的消息状态，避免同一问题重复扣费或重复记忆。外部模型的计费无法保证绝对 exactly-once，失败重试须有明确次数与状态。

语音流程为用户主动录音 → 云端识别 → 同一套对话引擎 → 云端合成 → 客户端播放。识别失败可以重录，合成失败仍显示文字。浏览器禁止自动播放时显示手动播放按钮。音频结果按消息和所有者关联，不能被另一个用户取得。

角色状态以实际交互驱动：录音中聆听，等待回复时思考，实际播放音频时说话，停止或失败后回待机。点击反馈优先本地执行，不要求每次都调用模型。养成数值不在首版范围内。

### 动作按钮与直接互动

用户希望像宠物应用一样，通过交互按钮让鱼做动作；当前未提供特定参照应用的素材或动作清单，不假设已确认其外观与细节。

建议首轮提供约 4～6 个动作，候选为摸摸（靠近或蹭手）、喂食（吃食动画）、转圈、跳跃、开心（摇尾或吐泡泡）和休息（闭眼休息，可唤醒）。这些是待用户选择的体验建议；喂食首版只是互动动画，不引入饥饿、货币、道具购买或完整养成体系。

按钮带文字标签，支持触摸和鼠标/键盘操作。点击后立即给出反馈，在客户端播放对应二维动画，结束后回到合适的状态；休息由明确的唤醒操作退出。动作可附带预设短音效或短句，不默认每次调用模型。聊天与角色基础动作仍共享同一大肥鱼形象。

首版动作属于当前设备的临时表演，不写入长期记忆、不要求跨设备同步；账号关系和持久状态仍按用户隔离。断网且程序资源已缓存时，纯本地动作仍可使用，但不宣称离线 AI 聊天可用。

每次只播放一个主动动作，连续点击不无限排队；录音或说话期间避免动作音效干扰麦克风和回复播放，可暂时禁用冲突动作并说明原因。停止、失败、离开页面和切换账号时清理动画与音频，不能残留上一用户的回应。支持系统减少动态效果偏好。

动作素材采用原创二维绘制、精灵动画或可变形素材，也可在满足许可后复用 dsh-pet 已发布动画；简单平移缩放能验证交互，但进食、翻身等效果需要匹配素材。最终风格和精细度影响美术工作量，不能仅凭按钮数量保证完成时间。

用户新增要求：调查 DSH 桌宠动作能否合法整体获取和复用。已找到对应的 `PC2005-cloud/dsh-pet`，核查版本有 114 个 WebM 文件，约 55.15 MiB。代码为 MIT；README 单独说明动画/提示词/源视频需参考角色授权，大肥鱼形象为 CC BY-NC-SA 4.0（署名、非商业、相同方式共享），不可将素材混同 MIT。用户随后明确接受非商业复用并要求开发。已下载并逐项核对固定版本动画的 Git blob SHA，保留署名及许可；未引入不明字体、表情包和音效，未运行上游制作脚本。详见 [复用调查](../../dsh-pet-reuse-research.md)。

若后续选择复用：保留来源及许可，按需加载动作；继续使用本项目多用户后端，不公开上游无鉴权的本机接口。必须另测 Safari/iPhone 透明动画，不能假设上游 MOV 素材与当前 WebM 数量一致。

## 数据、备份与恢复

数据库是云端业务主数据源，客户端缓存和本地备份不是另一套可同时编辑的主数据。首版单实例，不实现多主同步。

最低备份目标：云端每日生成一致性加密快照，保存到与应用磁盘独立的位置，保留 7 个日备份；电脑在线时下载最新可用副本。密钥与备份分开保存，不能只存于一台可能关机的电脑；具体存储与密钥保管方式在付费部署前落实。

目标为在独立云备份正常运行时最多损失约 24 小时数据；初期人工恢复目标 4 小时，不是可用性 SLA。备份失败产生可见告警，不能把“上传了文件”等同于可恢复。

必须使用 SQLite 一致性备份机制，不能随意复制运行中的主文件而遗漏 WAL。恢复演练在隔离环境执行，验证账号、消息、记忆、权限和删除记录，记录实际恢复时间。生产恢复需额外确认目标和停写窗口。

## 阶段与验收（不是详细实施任务表）

1. **基础与隔离**：独立 App 入口、邀请注册、登录、数据库迁移及两账号文字对话。验收甲乙各有可辨认记忆，越权请求均失败，甲的内容不进入乙的实际模型输入；QQ 原有行为无回归。
2. **云端可靠运行**：持久化、消息去重、限流、错误提示、云端备份与恢复。验收本地 WSL 关闭后可用，应用重启/重部署不丢数据；删除后恢复不重新暴露内容。
3. **PWA 与二维角色**：前台跨设备使用、六类状态、约 4～6 个待选动作按钮、安装引导、会话状态与退出清理。验收目标手机/电脑实测、同账号续聊、换账号不串缓存；按钮与角色动作对应，连续点击不堆积，休息可唤醒，录音/说话无动作音效干扰。最终美术未定时用明确标记的原创占位角色，不将其视为定稿。
4. **语音闭环**：录音上传、ASR、TTS、播放停止与失败降级。验收权限拒绝、超时、短断网、不同浏览器录音格式、重复发送和音频越权。
5. **家人朋友试用**：邀请少量真实使用者，测试容量基线和恢复流程，记录响应耗时、失败率和模型/语音用量，按预算决定是否扩大。

可交互体验版粗估 10～20 个开发工作日；含多人隔离、语音兼容、备份恢复的首版粗估 4～8 周。属于初步工程估算，不是交付日期；美术、服务商选型及实机问题会改变估算。

## 风险与后续决策

- 服务端算力不等于模型能力；第一版优先调用外部模型，不默认购买 GPU 或搬迁本地模型权重。
- 生产费用由应用实例、持久存储、备份、模型和语音共同构成；预算未确认前不创建付费资源。
- 提供商、录音格式和响应速度先做小规模验证，再扩大实现；不预先承诺即时语音效果。
- 最终角色形象、是否复读变声、关系称呼规则是体验细化项，可先采用原创占位素材和普通昵称称呼；不影响基础账号/数据设计。
- 第一轮邀请限定熟人；正式公开发行、未成年人专门服务、商店审核及商业化另立范围。
- 未来 QQ 账号绑定、多人群聊、原生应用、实时语音、三维动画均为后续变更，不自动包含在首版承诺中。

## 交给实施者的选择空间

在不改变以上边界的前提下，实施者可决定具体目录组织、HTTP 接口名称、UI 组件、CSS 与二维动画技术、SQLite 表和索引、会话实现库、测试工具及备份调度方式。优先复用现有模块和成熟标准能力，不为假设中的规模增加基础设施。

后续执行见 [实施计划](../plans/2026-11-13-dafeyu-pwa.md) 与 [验证记录](../plans/2026-11-13-dafeyu-pwa-validation.md)。用户开始开发的授权不等于购买付费云资源的授权。
